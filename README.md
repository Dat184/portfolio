## About this repo

This is the site I send to recruiters: who I am, what I work with, the projects I've built, and how to reach me. It's written to be read by HR in a few seconds and by tech leads in more depth.

Next.js 16 generates the pages at build time using React 19 and TypeScript. Vercel is the planned deployment target.

## How I work with AI

I keep design specs and agent instructions in this repo.

- Every change starts as a spec and a plan, using the [superpowers](https://github.com/obra/superpowers) workflow: brainstorm, write the spec, approve it, write the plan, then implement. Both live in `docs/superpowers/`.
- UI work goes through Hallmark, which checks pages against common tells of generated design.
- Content comes only from `content/`. The agent is not allowed to invent facts about me.
- Husky checks staged files, runs the type checker and tests, and validates commit messages.
- From the scaffold on, each change lands on `main` as a pull request merged by squash: one commit per reviewed change.

## Run locally

Use Node.js 24 and pnpm 12.8.1. From the repo root, run:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

With the pnpm version pinned in `package.json`, `pnpm-lock.yaml` contains two YAML documents. The first records the pinned pnpm executable. The second records the app dependencies. [pnpm lockfile format](https://pnpm.io/lockfile-format)

Open [localhost:3000](http://localhost:3000). To add a personal project, copy `content/projects/_template.mdx` to a file named for its URL, such as `content/projects/my-tool.mdx`.

`pnpm build` builds a local preview with visible placeholders. Run `VERCEL_ENV=production pnpm build` to check that the content and CV are ready to publish.

## Technical overview

Next.js generates the home page and MDX project pages at build time. The site has no backend or database. Tailwind CSS v4 scans `src/` for classes.

Content updates go through Git. The content loader reads YAML and MDX, validates the data with Zod, and renders project case studies with `next-mdx-remote`. See the [content model](content/README.md#content-model) for file formats and field definitions.

## Quality gates

Checks run locally through **Husky**. Once Vercel is connected, its build will also gate deployments.

| Hook | Runs |
|---|---|
| `pre-commit` | Reject commits on `main`, check staged files with ESLint and Prettier, run `next typegen` and `tsc --noEmit`, then run Vitest. |
| `commit-msg` | commitlint with the Conventional Commits types |
| `pre-push` | reserved for slow tests (e2e), if added later |

Prettier skips Markdown and MDX.

`.claude/` is third-party and agent tooling, not app code. It is excluded from ESLint, Prettier, lint-staged, TypeScript (`tsconfig` `exclude`), and Vitest, so hooks never reformat or type-check it. `skills-lock.json` is generated by the skills installer and is excluded from Prettier for the same reason.
